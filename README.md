### ดีไซน์ v2 (หรูหรา แต่ยังเป็นภาษาของ Manus)

โครงหน้าเหมือนเดิมทุกส่วน (Hero → แนวคิด → คอลเลกชัน → ฝากขาย → ติดต่อ) ปรับเฉพาะสัดส่วน ตัวอักษร และรายละเอียด หน้าแรกแบ่งสองฝั่งเหมือนเว็บเก่า: ฝั่งซ้ายพื้นดำมีหัวข้อ "MAKE YOUR SIGNAL." ฝั่งขวาเป็นภาพศิลป์ ส่วนบนจอแคบ (ต่ำกว่า 900px) ภาพจะขึ้นก่อนแล้วตามด้วยข้อความ

- **ฟอนต์** (ลิงก์ Google Fonts ใน `<head>` ของ `index.html`): Archivo สำหรับตัวอักษรอังกฤษ (ใช้แกนความกว้าง `font-stretch` ให้หัวข้อดูกว้างและหนา) ภาษาไทยใช้ Prompt กับหัวข้อ ปุ่ม และป้ายกำกับ (หนาและกว้างพอจะอยู่คู่กับ Archivo ตัวพิมพ์ใหญ่) และ Noto Sans Thai กับย่อหน้า (อ่านสบายในข้อความยาว)
- **สี** (ตัวแปรใน `:root` ของ `styles.css`): ดำ `#11100e`, ครีม `#f2e7d3`, แดง `#c9231c`, น้ำเงิน `#164f9b` เหมือน Manus ส่วนตัวอักษรเล็กสีแดงบนพื้นดำใช้ `--red-hi: #e8604f` เพราะแดงแบรนด์บนพื้นดำมี contrast แค่ 3.4:1 (ต้อง 4.5:1)
- **กริด** 12 คอลัมน์ กว้างสุด 1360px ขอบข้างและระยะห่างระหว่างส่วนเป็นตัวแปร (`--pad`, `--section-y`) ทุกส่วนมีเส้นบางและเลขลำดับ (01–04) เหมือนสไตล์ Manus
- **ภาษาไทย**: ไม่ใช้ตัวอักษรเว้นระยะหรือตัวพิมพ์ใหญ่กับข้อความไทย (ตัวแปร `--track-label` และ `--track-display` เปลี่ยนเป็นค่าเกือบ 0 เมื่อ `html[lang="th"]`) ระยะบรรทัดไม่ต่ำกว่า 1.15 ที่หัวข้อและ 1.95 ที่ย่อหน้า คำอังกฤษที่แทรกในประโยคไทยใช้ Archivo
- **คำไทย**: ใช้ "ตะกร้า" แทน "ถุง", "สั่งจองล่วงหน้า" แทน Pre-order, "ราคาจะแจ้งภายหลัง" แทน PRICE TBC ข้อความทั้งหมดอยู่ที่ `TRANSLATIONS` ใน `script.js` และข้อความตั้งต้นใน `index.html` ต้องตรงกับ `TRANSLATIONS.th` (ใช้เมื่อ JavaScript ไม่ทำงาน)
- ตะกร้า หน้าต่างสินค้า สลับภาษา และฟอร์มฝากขายของ Manus ยังทำงานเหมือนเดิม ปรับเพิ่มเฉพาะ: ใช้ `localStorage` แบบป้องกันการถูกบล็อก, สถานะในหน้าต่างสินค้าแปลตามภาษา, ฟอร์มฝากขายแจ้งตามจริงว่ายังไม่ได้ส่งถึงทีมงาน

สามชิ้นหลังคมน้อยกว่าสองชิ้นแรกเพราะต้นฉบับเป็นภาพแคปหน้าจอขนาดเล็ก เมื่อได้ไฟล์ต้นฉบับ ให้แทนที่ไฟล์ชื่อเดียวกันได้ทันที ไม่ต้องแก้โค้ด

จับคู่รูปกับสินค้าตามคำอธิบายสินค้าในหน้าเว็บ ถ้าสลับกันให้เปลี่ยนค่า `--plate` ของ `.product-image-1` ถึง `-5` ใน `styles.css`

การ์ด หน้าต่างรายละเอียด และตะกร้าอ้างภาพผ่านคลาส `.product-image-1` ถึง `-5` (ตัวแปร `--plate`) การ์ดเป็นสัดส่วน 1:1 ส่วน `--modal-fit`, `--modal-pos` และ `--thumb-size` / `--thumb-pos` ปรับการครอปในหน้าต่างและตะกร้าได้ต่อรูป

ถ้าจะใช้แท็ก `<img>` แทนภาพพื้นหลัง วางไฟล์ใน `site/assets/products/` (แนะนำ WebP สัดส่วน 1:1) แล้วเพิ่ม `<img>` ในการ์ดนั้นของ `site/index.html`:

```html
<div class="product-image product-image-1 has-photo">
  <span>KH / FS-01</span>
  <img src="./assets/products/fs-01.webp" alt="เสื้อ First Press Tee ด้านหน้า" width="1000" height="1000" loading="lazy" />
</div>
```

รูปจะเติมเต็มกรอบและทับภาพพื้นหลัง ป้ายรหัสสินค้า (`KH / FS-01`) ยังอยู่มุมซ้ายบน ถ้าจะให้หน้าต่างรายละเอียดและตะกร้าใช้รูปจริงด้วย ให้เปลี่ยนค่า `--plate` ของคลาส `.product-image-1` ใน `styles.css` เป็นไฟล์รูปจริง

## ขอบเขตสำคัญ

Repository นี้ยัง **ไม่ใช่ source code เต็มของเว็บไซต์ที่เผยแพร่** เนื่องจาก source code ต้นฉบับยังไม่ได้ถูกส่งเข้ามาใน Sandbox ขณะจัดทำ repository

ชุดนี้เป็น Landing Page แบบ Static สำหรับนำไปพัฒนาต่อ ยังไม่มี database, authentication หรือระบบ order จริง ดังนั้นไม่ควรนำส่วน `/track` และ `/admin/pre-orders` ไปใช้งาน production โดยตรง

ตะกร้าสินค้าในเวอร์ชันนี้เป็น client-side prototype: สินค้ายังมีสถานะ `PRE-LAUNCH` และ `PRICE TBC` จึงยังไม่เปิด checkout จริง ปุ่ม `REQUEST PRE-ORDER` จะเปิดใช้งานเมื่อเชื่อมราคาจริง ฐานข้อมูล และระบบรับคำสั่งซื้อแล้ว

ฟอร์มฝากขายในเวอร์ชันนี้เป็น draft form: หลังส่งข้อมูลจะเก็บเฉพาะข้อมูลแบบร่างไว้ใน `localStorage` ของ Browser เครื่องนั้น ยังไม่ได้ส่งเข้าอีเมล, LINE, database หรือระบบหลังบ้านจริง จึงต้องเชื่อม submission endpoint ก่อนใช้งานรับฝากขายจริง

Admin Dashboard ปัจจุบันอ่านข้อมูลจาก `localStorage` ชุดเดียวกับฟอร์มฝากขาย จึงเหมาะสำหรับตรวจ flow และ UI เท่านั้น ยังไม่มี Authentication และยังไม่ใช่ระบบ production จนกว่าจะเชื่อม Supabase Server API และเพิ่มสิทธิ์ผู้ดูแล

Admin Dashboard เวอร์ชันล่าสุดรองรับ Supabase Auth และตาราง `consignments` แบบ optional: คัดลอก `site/admin/supabase-config.example.js` เป็น `site/admin/supabase-config.js`, ใส่ Project URL กับ publishable/anon key, ตั้งค่า Auth user ให้มี `app_metadata.role = admin`, และรัน `docs/SUPABASE_CONSIGNMENTS_SCHEMA.sql` ใน Supabase SQL Editor จากนั้น Dashboard จะอ่านข้อมูลจาก Supabase และบันทึกสถานะอนุมัติ/ปฏิเสธลงฐานข้อมูลจริง ส่วนไฟล์ config จริงถูกกันไว้ใน `.gitignore` ไม่ให้ push ขึ้น GitHub

## ฝากขายมือสอง / รายการมือสอง (ร่าง)

- ฟอร์มฝากขายรองรับแบรนด์ KHARAWA และแบรนด์อื่น มีไซซ์ สภาพสินค้า รูปได้ 4 รูป และช่องยินยอม
- หลังกดส่งจะได้เลขอ้างอิง (`KH-C-YYMMDD-XXXX`) พร้อมปุ่มส่งรายการให้ทีมงานทาง LINE `@Kharawa` และปุ่มคัดลอกข้อความ
- ยังไม่มีการส่งข้อมูลอัตโนมัติ ข้อมูลเก็บในเบราว์เซอร์ของผู้กรอกเท่านั้น (รอเลือกช่องทางเก็บข้อมูล)
- ส่วน "มือสองคัดสรร" ในหน้าเว็บอ่านจากรายการ `PRELOVED_ITEMS` ใน `site/script.js` (ตอนนี้ว่าง จึงแสดงข้อความ "กำลังคัดสรรชิ้นแรก") เพิ่มชิ้นจริงตามรูปแบบที่เขียนไว้เหนือรายการ

## แชร์สินค้ามือสอง / แคปชั่น / วิดีโอ (ไม่ต้องใช้บัญชี)
- ปุ่ม "แชร์ / ทำโพสต์" ในการ์ดมือสองแต่ละชิ้น (`site/share.js`): ลิงก์แชร์ Facebook/LINE, คัดลอกลิงก์, แคปชั่นขายสร้างอัตโนมัติแยกตามช่องทาง (Facebook, LINE, YouTube, Shopee, Lazada) แก้ไขได้, และสร้างวิดีโอสไลด์โชว์จากรูปสินค้าในเบราว์เซอร์
- YouTube / Shopee / Lazada ยังโพสต์ให้อัตโนมัติไม่ได้ ต้องใช้บัญชีผู้ขายและ API ของแต่ละเจ้า ตอนนี้คัดลอกแคปชั่นแล้วเปิดหน้าลงขายให้
- `SITE_URL` ใน `share.js` เป็นค่าชั่วคราว ต้องเปลี่ยนเป็นโดเมนจริงตอนเปิดเว็บ
- ดูตัวอย่าง: เปิดเว็บแล้วเติม `?demo=preloved` (ใช้รูปสินค้า KHARAWA เป็นตัวอย่าง ไม่ใช่ของมือสองจริง)

- ทุก 30 นาที (และทุกครั้งที่ deploy) GitHub Actions รัน `scripts/build-share-pages.mjs` อ่านรายการ "ลงขาย" จาก Google Sheet แล้วสร้างหน้า `s/<เลขอ้างอิง>.html` ที่มีรูปและชื่อสินค้าใน og: tags ให้ Facebook / LINE แสดงการ์ดพรีวิวพร้อมรูป
- ปุ่มแชร์ใช้ลิงก์ `s/...` นี้ (ยกเว้นสินค้าตัวอย่าง) และมีลิงก์รูปสินค้าไว้โหลดไปอัปโหลดเองที่ Shopee/TikTok/YouTube
- ลงสินค้าแล้วอยากให้ขึ้นทันที: Actions → Deploy → Run workflow
